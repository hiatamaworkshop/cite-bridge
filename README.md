# cite-bridge

English: [README.en.md](README.en.md)（正本はこの日本語の版で、英語の版は訳である）

論文の引用ごとに、原典の逐語と所在を錨として持たせ、その確認の状態を執筆のあいだ正しく保つ道具である。

実験的な 0.x の道具で、AI と一緒に論文を書く人に向けている。約束するのはデータの形と保証の文の二つだけで（下の「何をする道具か」）、コマンドと出力の文は版ごとに変わりうる。

## 何をする道具か

引用の誤りの多くは、実在する文献に、その文献が言っていないことを言わせるものである。この道具は、それを自動で見抜くのではなく、
次の三つを毎回行う。

1. 原稿の一文と原典の逐語を並べて読む場を作る（`review`）。
2. 人が確かめた結果を、本文と根拠の指紋で固定する（`approve`、`apply`）。
3. 本文か根拠が後で変わったら、要再確認として知らせる（`check`）。

機械が保証するのは、錨（逐語）が原典に実在することと、その所在までである。原典が主張を支えているかは、人の承認が保証する。
そのため「検証ツール」とは呼ばない。支持の判定を機械に任せない代わりに、人が見る材料を毎回同じ形で揃える。

道具が約束するのは、データの形（抜き書きと引用の欄、指紋、判断ファイルなど。SPEC.md §11.1）と、上の保証の文の二つである。コマンドと機能は約束しない。データの形を変えるときは版を上げ、移し方を書き、古い形を次の版まで読む（SPEC.md §11.2）。

## 例

原稿の引用の直後に印を置く。

```markdown
話す入力は打つ入力より速いが、話した後に直す語は多かったという報告がある（Tanaka, 2024）〔c001〕。
```

原典の一箇所を、抜き書きのファイル（文献ごとの md）に逐語のまま写す。所在と照合の欄は道具が足す（`derive`）。

```markdown
## e1
逐語: Speaking was faster than typing, but participants corrected more words after speaking.
強さ: 観察
要約: 話す入力は打つ入力より速かったが、話した後に直した語は多かった。
言っていないこと: 直す時間を含めた全体の時間で、話す方が速いとは言っていない。
記入: AI 2026-11-07
```

引用のファイルに、印と同じ ID のブロックを書き、どの抜き書きが文を支えるかを結ぶ。

```markdown
## c001
種類: 主張
抜き書き: tanaka2024#e1
理由: 音声の入力は速いが、直す手間が残ることを、先行研究の結果として示す
原文との差: 言い換え
記入: AI 2026-11-07
承認: 未
```

人が原稿の文と逐語を並べて読んで承認すると、道具は承認の行と、本文と根拠の指紋を記録する。
承認の後に原稿のこの文か抜き書きを直すと、`check` は次を出し、確かめ直すまで提出前の検査（`check --strict`）が止まる。

```text
c001: 承認の後に本文が変わった。要再確認
```

上は主張（原典の内容を述べる）の引用である。指示（作品の名前や存在を挙げるだけ）の引用は書誌の key だけを持ち、承認を求めない。

## 始め方

初めてなら [docs/getting-started.md](docs/getting-started.md) で、この例の一式（`examples/first-citation/`）を使って一件の引用を最後まで通す。
ふだんの流れは次のとおり（リポジトリの根で実行する）。

1. 設定 `bridge/bridge.toml` を置く（ひな形は SKILL.md の「設定」）。書誌は keyline、BibTeX、CSL-JSON を読める。
2. 原本の PDF から抽出テキストを作る（`bridge.py extract`。Web 資料は `bridge.py snapshot <key>`）。
3. 抜き書きと引用を書き、原稿に印を置く。印の無い出典は `bridge.py propose` で作業票にできる。
4. `bridge.py derive` で導く欄を書き、`bridge.py check` で整合を検査する。
5. `bridge.py review --html -o review.html` の画面で人が判断し、保存した判断ファイルを `bridge.py apply <判断ファイル>` で書き込む。
6. 提出前は `bridge.py check --strict`、地点の記録は `bridge.py checkpoint`。

コマンドの全部、git の pre-commit の hook、原稿が複数あるときの `--citations` は SKILL.md にある。

## AI に使わせるとき

使う側のリポジトリの、エージェントが読む指示ファイルには、次の短いブロックだけを写す。作法の文書（SKILL.md）は写さずに指す。
写すと、道具の版が進むたびに写しがずれるからである。置き先は AGENTS.md、CLAUDE.md、GEMINI.md など、使っているエージェントが読むものを使う人が選ぶ。
パスは既定の置き場所（`tools/cite-bridge/`）と設定（`bridge/bridge.toml`）のものなので、替えていれば読み替える。

```markdown
## 引用（cite-bridge）

- 読む文書: 引用・抜き書きを書く前に tools/cite-bridge/SKILL.md を読み、その作法に従う。ファイルの形は tools/cite-bridge/SPEC.md。
- 確かめるコマンド: 書いたら `python tools/cite-bridge/bridge.py derive` と `python tools/cite-bridge/bridge.py check` を走らせ、ERROR を残さない。
  提出前は `python tools/cite-bridge/bridge.py check --strict`。
- 正本: 引用の確認の状態は、設定 bridge/bridge.toml が指す抜き書きと引用のファイルにある。`@` で始まる行は道具が書くので手で直さない。
```

## 限界

- 照合できるのは、抽出テキストか Web の写しがある文献だけである。PDF も Web の写しも無い文献は、照合できない格になる。
- 照合が近似一致の抜き書き、OCR の抽出、短い逐語などは、機械では逐語の実在を保証できない。道具は「要ヒューマンチェック」の印を付け、
  人か、人が委ねた外部の AI が原本で確かめた記録を待つ（SKILL.md の「要ヒューマンチェック」）。
- 印の無い出典（印を置いていない引用）は、この道具が確かめていない。`check` の「網羅」の行と `coverage` がその数と一覧を出す。
- 承認が形だけになっていても、道具は検出できない（頁の画像を開いたか等は記録しない）。防ぐのは事故で、悪意は防がない。
- 見出し（節）の検出は推定である。

## 動かすのに要るもの

- Python 3.11 以上（標準ライブラリの `tomllib` を使う）。
- 標準ライブラリだけで動く。PDF の抽出（`extract`、PDF の URL の `snapshot`）にだけ `pymupdf` が要る。

## 言語

- 文書の正本は日本語で、英語の版（`*.en.md`）は訳である。
- 出力の文（`check` や `review` が出す文、承認の HTML の画面の文）は、いまは日本語だけで、道具は翻訳の仕組みを持たない。
  替えたい人は使う側で `cite_bridge/` の中の文を直す。出力の文は約束する範囲の外である（SPEC.md §11.1）。
- 欄の名前と値は英語の別名でも書ける（`verbatim:`、`strength: observation` など。SPEC.md §10）。道具が書く導く欄（`@` の行）の名前は、設定の `[output] language = "en"` で英語になる。
- 英語の原稿では、設定の `sentence_end` を英語の文の終わりに替える（SKILL.md の「設定」）。
